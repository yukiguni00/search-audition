# オーディション2ndステージ EAST 表示ガイド

更新日：2026-10-23

この文書は、出演者検索サイトの **2ndステージの公演カード**をスマートフォンで読みやすくするために採用した表示ルールを記録します。2026年10月30日公演で適用済みです。デザインは運用に合わせて見直して構いません。

## 基本方針

- **出演者・香盤順を主役にする。** 日時と開演時刻は明確に、会場名や補足情報は控えめに表示する。
- **元データと表示用データを分離する。** 正式会場名・開場時刻・発表履歴を削除しない。**お気に入り欄と公演カードは同じ表示用会場名を参照**して表記が食い違わないようにする。
- **未発表情報は推測で補完しない。** 出演部が未発表なら、確定済み進出者と公演枠を区別する。
- 公式香盤公開後は部別の出演者一覧を香盤順で表示する。正式香盤にない変更は推測して加えない。

## 確定した表示ルール（2026-10-23）

| 項目 | 表示ルール | 保存方法・注意点 |
| --- | --- | --- |
| 会場名 | **公演カードとお気に入りの出演予定欄に共通の短い名称**を表示。2ndカードの会場は日時よりやや小さい **`1rem`・太字（`700`）・`#555`** | `venue` に正式名称、必要な場合だけ `venueDisplayName` に短縮表示名を保存。どちらの画面も `getDisplayVenue()` で表示名を取得し、別々に表記を管理しない |
| 追加合格者 | 該当する出演者チップの末尾に小さい **「追加」** ラベルを表示 | 元の1st公演の `additionalQualifiedPerformers` を元に判定。「追加」は「追加合格者」を意味することを出演者欄で説明 |
| 開場時間 | 10/30の2nd公演カードでは表示しない。日時の「開演」を優先 | `openTime` は残し、カードで非表示にしたい場合だけ `hideOpenTime: true` を設定。指定のない旧公演は従来表示 |
| 発売情報 | **「一般発売開始：10月24日(土)10:00」** のように、発売開始を簡潔に表示 | `ticket.saleInfo` に確定した発売開始のみ登録。受付終了日時を削除する場合も元資料の内容を取り違えない |
| チケット | 開演部ごとに正しいFANYリンクを表示 | `ticket.url` を各部のイベントに紐づけ、別の部のURLを流用しない |

### 10/30の登録例（抜粋）

```json
{
  "eventType": "audition-2nd-east",
  "venue": "R'sアートコート（労音大久保会館）",
  "venueDisplayName": "R'sアートコート",
  "openTime": "13:15",
  "hideOpenTime": true,
  "time": "13:30",
  "ticket": {
    "saleInfo": "一般発売開始：10月24日(土)10:00",
    "url": "https://ticket.fany.lol/reception/67769/53893"
  }
}
```

**備考：** 上は表示項目の抜粋。実データには `id`、`date`、`timeMinutes`、`performers` などが必要です。会場名、開場時刻、料金、発売日、出演部数は次回以降も同じとは限らないため、毎回公式情報で確認します。

## 追加合格者を表示する仕組み

1. 1st公演側に通常合格の `qualifiedPerformers` と追加合格の `additionalQualifiedPerformers` を**区別して保持**する。
2. 進出先は `qualifiedNextStageDate` で紐づける。
3. 2nd公演では名前を照合して「追加」を表示する。見た目のラベルを短縮しても、判定元データや追加合格17組の履歴は変えない。
4. 2026年10月30日の正式香盤は第一部23組・第二部24組・第三部23組、計70組（通常合格53組、追加合格17組）。この数字は**今回の検証値**であり、次回の固定値ではない。

## 次回更新のチェックリスト

- [ ] 公式の公演日・会場・開演時刻・チケットURLを各部に正しく紐づけた
- [ ] `venue` は正式表記のまま、`venueDisplayName` の必要性を確認した。公演カードとお気に入り欄の双方で短縮表示が一致することを確認した
- [ ] `openTime` を消さず、非表示にする公演だけ `hideOpenTime` を設定した
- [ ] `ticket.saleInfo` の発売開始表記を公式情報に合わせた
- [ ] 正式香盤の出演順、トリ、組数を全件確認した
- [ ] 追加合格者の識別・プロフィールリンク・お気に入り・検索に問題がない
- [ ] `data/events/YYYY-MM.json`（編集元）と `data/events.json`（集約）が一致することを確認した。可能なら `npm run data:check` も実行した
- [ ] UI変更時は `index.html` のJS/CSSキャッシュ更新用バージョンも更新した

## レイアウト方針の扱い

2026年10月に試した「B案（進出者を先に大きく表示し、部別公演情報を後に置く）」は、**表示改善の検討案**であって、この文書では今後の固定レイアウトとして採用しません。正式香盤が出たら各部の出演者カードが中心になる現在の仕様と、上記の読みやすさのルールを分けて扱います。
